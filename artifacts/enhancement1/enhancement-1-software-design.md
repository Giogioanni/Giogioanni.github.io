# Enhancement Plan/Overview: Software Design & Engineering
--------------------------------------------------------------

## Justification for inclusion and how the enhancement improved the artifact
I selected this artifact because it showcases foundational software development skills that employers should expect from the get-go: implementing clear business rules, building a service layer, and validating behavior with automated tests. This enhanced version I edited strengthens the artifact in three different ways. 1st I improved the robustness by replacing the mutable java.util.Date type with the immutable java.time.Instant for appointment timestamps, reducing the risk that an appointment’s date can be changed after creation. 2ndly I improved error-handling clarity by introducing more specific exception types for invalid appointments, duplicate IDs, and missing records. 3rdly I expanded the unit test suite with boundary cases and additional service behaviors like not-found lookups and delete-then-read, improving confidence that my code meets requirements and remains stable during future enhancements.

## Course outcomes and updates to outcome coverage plans
My enhancement supports the course outcomes I planned to target in Module One. It shows professional-quality communication and software engineering practices through clearer code structure, improved validation messaging, and documentation updates. I believe it also demonstrates a security mindset by anticipating adversarial or accidental misuse such as mutating time values and mitigating that risk with safer data types and stronger input checks. My outcome-coverage plan remains the same overall which is that Milestone Two focuses on software design and engineering quality; Milestone Three will extend this solution using additional algorithms/data structures for date-based querying; and Milestone Four will add database persistence using a repository layer and secure query practices.

## Reflection on the enhancement process (what I learned and challenges I faced)
Enhancing this artifact reinforced the importance of designing software so that invalid states are difficult or impossible to represent. By enforcing validation in the domain model and using immutable time types, the system overall becomes safer and easier to reason about. A significant challenge was updating the tests and API expectations after changing the date representation; This also highlighted the value of automated testing as a safety net during refactoring. In conclusion, the artifact has a more professional feel now, is easier to maintain, and is better positioned for upcoming capstone enhancements I am going to make such as adding efficient date-range queries and database persistence.
