# Professional Self-Assessment

Throughout my Computer Science program at Southern New Hampshire University, I developed a stronger technical foundation and a clearer professional direction: building reliable software that solves real problems while balancing performance, maintainability, and security. Course projects/milestones required me to move beyond “getting code to work” and instead actually focusing on engineering practices that employers expect—clean design, meaningful testing, readable documentation, and the ability to explain decisions to nontechnical audiences. Building this ePortfolio helped me bring those skills together into one cohesive story and present my growth with concrete evidence. As I prepare to enter the field, I am confident in my ability to contribute as a developer who can learn quickly, communicate clearly, and deliver solutions that are practical and secure.

Collaboration and communication have been central to my growth, even in an online environment. In multiple courses, I practiced planning work in stages, refining deliverables based on feedback, and documenting decisions in a way that teammates and reviewers can follow. This capstone reinforced those habits by requiring an informal code review, milestone submissions, and revision cycles that mirror professional development workflows. I have also gained experience communicating with different “stakeholders,” such as classmates and instructors acting as managers or clients, by translating technical ideas into clear outcomes (what the software does, why changes matter, and how success is measured). That ability to communicate is part of what makes a technical portfolio effective, and it is a skill I intend to keep strengthening in professional environments.

My work across the program strengthened my understanding of data structures and algorithms as practical tools for solving problems efficiently. I learned to choose structures based on trade-offs like speed, memory use, and simplicity—for example, selecting constant-time lookups when identifying records by unique keys, and using sorting or filtering approaches when the problem shifts from “find by ID” to “organize by time or priority.” These decisions are not purely academic; they determine how software behaves as data grows and how understandable the code remains over time. In the capstone, I applied this mindset by emphasizing correctness, efficiency, and clear behavior under edge cases, supported by tests.

In software engineering and databases, the program taught me to design systems that are maintainable and extensible rather than tightly coupled or fragile. I learned to separate concerns like models, service logic, persistence, apply defensive validation, and create interfaces that keep code flexible as requirements change. I also developed stronger database awareness by working with structured data concepts and then applying persistence in a way that supports real application needs. In the capstone, the shift from an in-memory approach to a persistent store reflects how software evolves in the workplace; prototypes become production-ready systems through careful refactoring, tooling, and repeatable build processes.

A consistent theme throughout my coursework has been building a security mindset. I learned that security is not a feature added at the end—it is shaped by design choices such as validation rules, error handling, dependency management, and how data is stored and accessed. In practice, that means limiting invalid input, reducing unintended state changes, using safe patterns for interacting with external resources, and ensuring the system behaves predictably even when something goes wrong. The capstone reinforced this mindset through an emphasis on identifying weaknesses early during review, then mitigating risk through clearer boundaries, improved validation, and more disciplined testing.

Together, the artifacts in this ePortfolio represent my growth across three core areas: software design and engineering, algorithms and data structures, and databases. Each enhancement builds on the same foundation and shows progression from a working baseline toward a more professional solution: cleaner architecture, stronger validation and testing, better data handling decisions, and persistent storage aligned with realistic requirements. My goal with this portfolio is not only to show that I can write code, but also to demonstrate that I can engineer software thoughtfully—making trade-offs intentionally, documenting decisions, and producing work that others can understand, run, and maintain. The pages that follow include my code review, original and enhanced artifacts, and narratives that connect each improvement to program outcomes and professional standards.
